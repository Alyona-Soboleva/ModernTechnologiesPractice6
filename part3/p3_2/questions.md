# Вопросы по Hibernate - Часть 3

## Вопрос 1: JDBC vs Hibernate

**Вопрос:** В чем разница между JDBC и Hibernate?

**Ваш ответ:**

JDBC (Java Database Connectivity):
1) Низкоуровневый API - прямой доступ к SQL командам
2) Ручное управление - нужно самим открывать/закрывать соединения, обрабатывать ResultSet
3) SQL-запросы - пишутся явно в виде строк
4) Отсутствует переносимость - SQL может быть зависим от конкретной БД
5) Больше кода - нужно писать много повторяющегося кода для каждой операции
6) Нет кэширования - все запросы напрямую идут в БД

Пример: ResultSet rs = stmt.executeQuery("SELECT * FROM users"), затем вручную создавать объекты

Hibernate (ORM):
1) Высокоуровневый фреймворк - работа с объектами Java
2) Автоматическое управление - сессии, транзакции, подключения управляются автоматически
3) HQL/JPQL запросы - работа с классами и полями, не с таблицами
4) Переносимость - один и тот же HQL код работает на разных БД
5) Меньше кода - CRUD операции в 1-2 строки
6) Встроенное кэширование - первый, второй уровень кэша
7) Lazy loading - загрузка данных по требованию
8) Автоматическое маппинг - ResultSet → объекты без лишнего кода

Пример: session.persist(movie) - одной строкой сохраняем объект

## Вопрос 2: HQL vs SQL

**Вопрос:** Что такое HQL и чем он отличается от SQL?

**Ваш ответ:**

HQL (Hibernate Query Language) - это объектно-ориентированный язык запросов, встроенный в Hibernate.

Основные отличия HQL от SQL:

Оперирует с разными сущностями:
HQL работает с Java классами и их полями
SQL работает с таблицами и столбцами в базе данных

Примеры запросов:
HQL: FROM Movie WHERE genre = 'sci-fi' (Movie - это имя Java класса)
SQL: SELECT * FROM movies WHERE genre = 'sci-fi' (movies - это имя таблицы)

Переносимость между базами данных:
HQL не зависит от конкретной СУБД, один и тот же запрос работает на разных БД
SQL может быть зависим от диалекта конкретной базы данных

Поддержка наследования:
HQL поддерживает полиморфные запросы и наследование сущностей
SQL не поддерживает наследование напрямую

Параметры запросов:
HQL использует именованные параметры: :name
SQL использует позиционные параметры: ?

## Вопрос 3: Аннотации Hibernate

**Вопрос:** Какие основные аннотации Hibernate используются на сущности Movie?

**Ваш ответ:**

В сущности Movie используются пять основных аннотаций.
@Entity - помечает класс как сущность, которую нужно сохранять в базу данных.
@Table(name = "movies") - указывает имя таблицы в БД. Если не указать, Hibernate использует имя класса.
@Id - обозначает поле, которое является первичным ключом. Обязательна для каждой сущности.
@GeneratedValue(strategy = GenerationType.IDENTITY) - определяет стратегию автоматической генерации ID (как AUTO_INCREMENT).
@Column - настраивает отображение поля на столбец таблицы. Параметр name задает имя столбца, nullable = false добавляет ограничение NOT NULL. Для поля year используется экранирование `year`, так как это зарезервированное слово в H2.

### Ответ 1: JDBC vs Hibernate

**JDBC (Java Database Connectivity):**
- Низкоуровневый API для работы с БД
- Прямая работа с SQL запросами
- Ручное управление соединениями
- Ручное маппинг ResultSet → объекты
- Больше boilerplate кода

**Hibernate (ORM):**
- ORM (Object-Relational Mapping) фреймворк
- Работа с объектами, а не с SQL
- Автоматическое управление сессиями
- Автоматическое маппинг объектов ↔ таблицы
- Меньше кода, выше абстракция
- HQL вместо SQL (хотя SQL тоже можно)

### Ответ 2: HQL vs SQL

**HQL (Hibernate Query Language):**
- Объектно-ориентированный язык запросов
- Работает с классами и полями, не с таблицами и столбцами
- `FROM Movie WHERE genre = 'sci-fi'` - Movie это класс, genre это поле
- Переносим между разными БД (Hibernate генерирует нужный SQL)
- Поддерживает наследование, полиморфизм

**SQL:**
- Структурированный язык запросов
- Работает с таблицами и столбцами
- `SELECT * FROM movies WHERE genre = 'sci-fi'`
- Зависит от диалекта БД

### Ответ 3: Аннотации Hibernate

**Основные аннотации на сущности Movie:**

1. **@Entity** - помечает класс как JPA сущность
2. **@Table(name = "movies")** - указывает имя таблицы в БД
3. **@Id** - помечает поле как первичный ключ
4. **@GeneratedValue(strategy = GenerationType.IDENTITY)** - автогенерация ID
5. **@Column(name = "title", nullable = false)** - настройка столбца:
   - `name` - имя столбца
   - `nullable` - может ли быть NULL

**Дополнительные распространенные аннотации:**
- **@OneToMany**, **@ManyToOne** - связи между сущностями
- **@Temporal** - для полей Date/Calendar
- **@Enumerated** - для enum полей
- **@Transient** - поле не сохраняется в БД
